# World Egg Names & Titles Pass

## Reference Guide for GameBibleV2

**Purpose:** A late-development reference for reviewing and revising proper names, cultural terminology, place names, epithets, institutions, creature names, quest/story titles, and other named setting elements across **GameBibleV2**.

**Primary principle:**

> A name should not feel real because it sounds like fantasy. It should feel real because it belongs to something.

A successful naming pass should therefore improve the **relationships between names**, not simply make individual words prettier.

# 1. What the Names Pass Is For

The final names pass should answer four questions:

1. **Does this name belong to the people, place, institution, or historical layer that produced it?**
2. **Does it remain distinct from neighboring names without feeling unrelated to them?**
3. **Can another person reasonably read, remember, and pronounce it?**
4. **Does its continued existence tell us something about the setting?**

The pass is **not** an exercise in replacing every ordinary word with an invented one.

World Egg should continue to contain things called:

- Father Sun
- Mother Moon
- Soul-Road
- Great Glass Desert
- The Boatman
- People of the Lamp
- Blood-Briar Guests
- Thirty Sisters

alongside things such as:

- Vorthara
- Grenzburg
- Qiryath Reqa
- Atheria
- Strazgorod
- Solzareth

Plain language and invented language should exist beside each other.

That contrast helps the invented vocabulary feel more credible.

# 2. The Rule Above Every Other Rule

## Do not ask:

**“What sounds right for this?”**

Instead ask:

**“What is this name allowed to be?”**

Choosing desirable ingredients too early encourages everything to converge.

For example:

> “I want this culture to sound elegant, so I will use long names, lots of vowels, and `ae`.”

That has already predetermined the answer.

Instead establish constraints:

> No `ae`.
>
> Avoid initial vowels.
>
> No word may end in `-is`.
>
> Personal names should normally fit in two or three syllables.
>
> Older settlement names may preserve consonant clusters that modern personal names have lost.

Constraints create a space in which unexpected names can occur.

# 3. Preserve Existing Canon Controls First

Before reviewing a name, determine whether it is actually available for revision.

The current repository already contains naming decisions that function as canon controls.

In particular, `00 Start Here/Current Focus Board.md` establishes that:

- **Grenzburg** and **von Grenzmark** are locked.
- the **Jirahar naming register** is locked;
- the **Covenant naming register** is locked;
- the **Nsizwa naming register** is locked;
- established cultural vocabulary may intentionally differ from translated English titles.

A names pass should therefore begin with three classifications:

### LOCKED

Do not change unless deliberately reopening canon.

### SYSTEM-BOUND

The individual name may change, but it belongs to an established naming register.

### OPEN

No current authorial control prevents reconsideration.

Do this **before** deciding whether you like a name.

# 4. World Egg Already Has a Strong Naming Model

One of the better existing models is Eclessia.

`The Making of the Eclessians.md` does not give the entire region one generalized "Eclessian sound."

Instead, historical layers produce different registers.

### Latinate inheritance

Examples include:

- Aurelia
- Adrien
- Alessior
- Veridancia

### Vesari inheritance

Examples include:

- Orzova
- Strazgorod
- Helvgrad
- Radomir

### Markish inheritance

Examples include:

- Korrheim
- Brauvalis
- Grenzburg
- Adalmar
- Reinhardt
- Weyn

This should be the general model for the setting.

**History creates naming families. Geography merely puts those families beside one another.**

A border town should not automatically sound like every other town within the same modern country if its population, substrate, conquerors, language, and institutions came from somewhere else.

# 5. Related Does Not Mean Repetitive

The objective is:

**family resemblance without template duplication.**

Bad implementation:

- Valoria
- Caloria
- Maloria
- Saloria
- Taloria

Technically consistent.

Completely artificial.

Better relationships can come through:

- characteristic stress;
- common consonant behavior;
- preferred syllable lengths;
- historical roots;
- sound changes;
- recurring grammatical particles;
- patronymics;
- compounds;
- translated elements;
- obsolete words preserved in place names;
- spelling conventions.

A culture does **not** require every name to share an ending.

Two related words may have almost no visible overlap if centuries of sound change separated them.

# 6. Sound Is Only the Starting Point

Sound still matters.

Shorter names often feel harder or more immediate.

Longer names can feel ceremonial or elaborate.

Harsh consonants can create abrasion.

Open vowels can create softness.

But these are **ingredients**, not a naming system.

Use sound to establish the first version.

Then become willing to destroy that version.

# 7. Rebuild Instead of Editing

When a name feels approximately right but not convincing, do not repeatedly modify the existing spelling.

Rewrite the entire word.

Example process:

**Version 1**
Caliscar

**Version 2**
Coleskar

**Version 3**
Kolescar

**Version 4**
Korskar

**Version 5**
Corsca

Each version should be written independently.

Do not protect the original simply because it came first.

Rewriting creates opportunities for accidental deviations.

Those deviations are often more useful than deliberate embellishment.

For every important name, generate at least:

- one conservative variation;
- one substantial reconstruction;
- one version that follows an unexpected direction.

# 8. Change the Appearance Without Necessarily Changing the Sound

A small orthographic change can transform the perceived character of a word.

Test:

- alternative vowels;
- doubled versus single consonants;
- `c` versus `k`;
- `i` versus `y`;
- compound boundaries;
- hyphenation;
- historical spellings;
- dropped initial or final sounds.

Do not use unusual spelling solely to make something look exotic.

The spelling should eventually belong to a writing tradition.

# 9. Let Roots Emerge

Do not require a complete constructed language before naming anything.

Instead allow repeated structures to appear naturally.

Suppose several independently developed names contain:

**var**

Do not immediately eliminate the repetition.

Ask:

**Could** `**var**` **mean something?**

Perhaps it originally meant:

- ford;
- enclosed ground;
- watch;
- old wall;
- salt water;
- royal holding.

Now inspect the locations containing it.

If their geography or history makes the connection plausible, you have discovered a root.

The next appearance of `var` can be intentional.

Eventually:

**names → patterns → roots → historical language**

rather than requiring:

**complete language → vocabulary → names**

# 10. A Root Should Create Worldbuilding

A discovered root is valuable when it explains something.

Suppose an old word meaning **shore** appears in the name of a settlement currently far inland.

Do not automatically discard the root.

Ask why.

Perhaps:

- the coast moved;
- a lake dried;
- the settlement migrated but retained its name;
- colonists reused an ancestral name;
- outsiders misunderstood the original word;
- the element changed meaning;
- the modern spelling hides a different original root.

A naming inconsistency can become geology, migration, conquest, or cultural memory.

That is preferable to perfect linguistic neatness.

# 11. Names Should Accumulate History

For major places, people, supernatural entities, and institutions, consider whether several naming layers should coexist.

Possible layers include:

### Endonym

What its own people call it.

### Exonym

What outsiders call it.

### Translation name

The readable English equivalent used by the encyclopedia.

### Archaic name

What older documents call it.

### Religious name

What a particular faith calls it.

### Administrative name

What states, churches, armies, courts, or maps call it.

### Colloquial name

What ordinary people call it.

### Insult or rival name

What enemies call it.

Not every entity needs all of these.

Major ones sometimes should.

# 12. The Menhir and Idols Are Already Using This Correctly

`Names of the Menhir, Masks of the Idols.md` provides a strong template.

The encyclopedia can say:

**Father Sun**

while another tradition says:

**Solzareth**

Likewise the creator reference can use:

**Wrath**

while cultural or deeper terminology uses another identity or title.

That distinction should be preserved.

It solves an important problem:

**reader clarity and world authenticity do not have to use the same vocabulary.**

Use plain translation names where they make the setting easier to understand.

Use culture-specific language where culture itself matters.

# 13. Material Life Comes First

`Setting Commandments.md` establishes that ordinary human reality is the setting's foundation.

The naming system should follow the same rule.

Most names should feel as though they could actually be used by:

- mothers;
- soldiers;
- priests;
- clerks;
- dockworkers;
- debt collectors;
- magistrates;
- merchants;
- shepherds;
- children;
- gravekeepers.

Do not write every mortal name as though it needs to announce:

**IMPORTANT FANTASY CHARACTER.**

A farmer and an emperor can belong to the same linguistic world without possessing equally dramatic names.

Ordinary names make extraordinary names stronger.

# 14. Historical Wounds Should Affect Names

Another Setting Commandment is that history leaves wounds.

Naming should preserve some of them.

Look for:

- renamed conquered cities;
- disputed place names;
- translated colonial names;
- restored ancestral names;
- religiously replaced personal names;
- obsolete imperial spellings;
- border towns with two common names;
- families retaining older surnames;
- districts preserving vanished populations;
- administrative terminology surviving dead governments;
- saints whose local names differ from official names.

A world with thousands of years of conquest and migration should contain messy nomenclature.

Do not clean all of it up.

# 15. Pronunciation Test

Readers will pronounce invented words incorrectly.

The objective is not to prevent variation.

The objective is to prevent catastrophic ambiguity.

For every important invented name:

### Read it without context.

Ask:

**How many reasonable pronunciations can I produce?**

Then ask:

**Do those pronunciations still sound like versions of the same name?**

Good:

> Two readers disagree slightly about vowels or stress but clearly recognize the same word.

Problem:

> Two readers would produce fundamentally different words.

Be especially suspicious of:

- unexplained vowel clusters;
- ambiguous `y`;
- unusual consonant combinations;
- silent-looking letters;
- strings with several equally plausible syllable breaks.

If a difficult spelling is culturally important, establish pronunciation through dialogue, rhyme, transliteration, or an explicit guide.

# 16. The “Veor Test”

A name does not necessarily fail because it sounds generic.

It may fail because **everything surrounding it sounds generic in exactly the same way.**

When reviewing any name, inspect ten nearby names.

Ask:

### Does this stand out because it genuinely belongs here?

or

### Does everything here sound like ten variations generated from the same fantasy-name prompt?

Flag clusters where unrelated names repeatedly rely on:

- the same suffix;
- the same vowel pattern;
- the same length;
- the same classical ending;
- the same apostrophe convention;
- the same harshness;
- the same pseudo-Latin morphology.

Repeated patterns are useful **only when the setting can explain the repetition.**

# 17. Special Warning for the Cosmology Pass

The cosmological corpus contains many constructed names with broadly high-fantasy/classical shapes.

That is not inherently wrong.

Names such as:

- Astaroth
- Lyraxis
- Orionis
- Hecatara
- Typhonius
- Arachnara
- Zephyraxis
- Morvalis
- Nevaura
- Veradia

should therefore not be individually rejected merely for sounding fantastical.

During the final pass, review them **as a population**.

Ask:

- Which are genuinely Atherian names?
- Which predate Atherian culture?
- Which are translations?
- Which are retrospective imperial names?
- Which names should have older forms?
- Which similarities indicate actual common linguistic ancestry?
- Which similarities exist only because they were designed using the same fantasy aesthetic?

The objective is not automatically to replace these names.

It is to determine **why they resemble one another**.

If there is no in-world answer, that is a reason to reconsider some of them.

# 20. Titles Need a Separate Pass

Names and titles should not be treated identically.

There are at least four types of title in GameBibleV2.

## A. Production and Reference Titles

Examples:

- `Current Focus Board`
- `Geography Atlas`
- `Narrative State Register`
- `Bestiary Translation Concordance`

These should prioritize **clarity and searchability**.

Do not make internal production documents poetic simply because the setting prose is poetic.

## B. Encyclopedia Article Titles

These should communicate the article's subject immediately.

Prefer:

**Atherian Imperial Age**

over something metaphorical if the article is actually the reference article for the period.

Poetry belongs beneath the organizational layer.

## C. In-World Titles and Epithets

These can be culturally specific.

Good sources include:

- occupation;
- physical location;
- an infamous event;
- legal terminology;
- religious ritual;
- local proverb;
- battlefield nickname;
- family relationship;
- deliberate insult;
- historical misunderstanding.

A title should sound like something **people started saying**, rather than something an author attached afterward.

## D. Quest and Story Titles

Avoid relying on the same title construction repeatedly.

Common patterns to monitor include:

**The [Adjective] [Noun]**

**The [Noun] of [Noun]**

**[Noun] Without [Noun]**

**[Number] [Nouns]**

None of these patterns are bad.

Repetition across dozens of quests makes the author's hand visible.

Whenever possible, derive a title from something inside the actual content:

- a line of dialogue;
- local saying;
- legal phrase;
- physical object;
- song;
- accusation;
- place name;
- promise;
- document;
- ritual;
- joke;
- misunderstanding.

The title then belongs to the story rather than merely describing its mood.

# 21. Use Translation Aggressively Where Appropriate

Not every local term needs to remain untranslated.

The existing canon already uses translated office and supernatural titles.

This is useful.

A culture can have a native word for a military office while the game calls it:

**Horn-Captain**

if the exact local phonetics add nothing to the scene.

Keep untranslated terms primarily when the word itself carries:

- theology;
- law;
- identity;
- historical argument;
- ritual significance;
- wordplay;
- social distinction that translation would erase.

Translation should increase accessibility without flattening culturally important distinctions.

# 22. Do Not Build Languages Merely to Justify Names

A complete conlang is unnecessary.

Build only as much linguistic structure as becomes useful.

Start with:

1. names;
2. recurring patterns;
3. discovered roots;
4. sound changes;
5. cultural terminology;
6. historical relationships.

Only formalize grammar where the project actually benefits.

The naming pass exists to support the world, not to turn GameBibleV2 into a linguistics project.

# 23. Recommended Order for the Final Names Pass

Do not rename the repository alphabetically.

Dependencies matter.

## Pass 0 — Protection Register

Inventory:

- locked names;
- locked naming registers;
- canonical terminology;
- translation conventions;
- names referenced by production systems.

Do not rename anything yet.

## Pass 1 — Peoples and Language Families

Review:

- cultures;
- ethnic identities;
- civilization names;
- language families;
- major historical populations.

These establish the systems everything else depends upon.

## Pass 2 — Major Geography

Review:

- continents;
- seas;
- major rivers;
- mountain systems;
- countries;
- historic realms;
- major cities.

Establish ancient geographical roots early.

## Pass 3 — Cultural Geography

Review:

- towns;
- districts;
- roads;
- forts;
- ruins;
- villages;
- estates;
- shrines.

Allow substrate and settlement history to become visible.

## Pass 4 — Personal Names

Review characters within cultural and historical cohorts rather than individually.

Compare:

- families;
- generations;
- classes;
- regions;
- minority communities;
- migrants;
- aristocracy;
- clergy.

## Pass 5 — Institutions and Offices

Review:

- churches;
- military organizations;
- guilds;
- noble houses;
- magical schools;
- legal offices;
- factions.

Prefer historically plausible institutional language over fantasy grandeur.

## Pass 6 — Cosmology and Creatures

Review supernatural terminology as connected systems.

Do not simply make every cosmic entity more exotic.

## Pass 7 — Quest, Story, and In-World Titles

Only after the world's vocabulary has stabilized.

This allows titles to borrow authentic setting language.

## Pass 8 — Collision Pass

Search the entire active vault.

Look for:

- nearly identical names;
- repeated initial syllables;
- repeated endings;
- confusing abbreviations;
- accidental rhymes;
- characters sharing names unintentionally;
- visually similar words;
- inconsistent spellings.

## Pass 9 — Pronunciation Pass

Read important names aloud without lore context.

Simplify where required.

# 24. Repository Migration Rule

Do not perform the final rename pass as hundreds of isolated edits.

Create a **Names Pass Rename Manifest**.

GameBibleV2 already has precedent for rename/migration manifests in previous reconstruction work.

Recommended columns:

| Old Name | New Name | Type | Culture | Reason | Canon Status | Aliases Retained | Files Updated | Notes |
| -------- | -------- | ---- | ------- | ------ | ------------ | ---------------- | ------------- | ----- |
|          |          |      |         |        |              |                  |               |       |

For each rename:

1. establish the replacement;
2. record it in the manifest;
3. search the active repository for the old name;
4. update article text;
5. update filenames where appropriate;
6. update Obsidian links;
7. update registers and indexes;
8. preserve an alias where historical references require it;
9. check archive material separately;
10. run another global search for the old name.

Do not assume changing the canonical article title completes a rename.

# 25. Three Rename Outcomes

Every reviewed name should end in one of three normal outcomes.

## KEEP

The existing name already belongs to the setting.

Do not rename something merely because a replacement is newer.

## REWORK

The underlying name works but needs:

- spelling change;
- shortened form;
- older variant;
- clearer pronunciation;
- different title;
- cultural localization.

This will probably be the correct choice surprisingly often.

## RENAME

Use when the existing name:

- belongs to no discernible naming system;
- conflicts with later cultural development;
- is repeatedly confused with something else;
- exists mainly because it “sounds fantasy”;
- causes serious pronunciation problems;
- creates an unwanted real-world association;
- breaks a now-established historical relationship.

# 26. Final Acceptance Test

A replacement should survive all of these questions.

### The Belonging Test

What does this name belong to?

### The Neighbor Test

Does it work beside ten surrounding names?

### The History Test

Why is this particular form used in 1360 AR?

### The Stranger Test

Could someone unfamiliar with the bible make a plausible attempt at pronouncing it?

### The Human Test

Could ordinary inhabitants actually say this name repeatedly in conversation?

### The Root Test

Does it create or participate in useful relationships?

### The Translation Test

Would plain language actually work better?

### The Veor Test

Is this interesting because of its relationships, or merely because it looks invented?

If the only defense is:

> “It sounds fantasy.”

keep working.

# 27. One-Minute Naming Card

When creating or revising a name:

**1. Identify its culture, era, and historical layer.**

**2. Check whether its naming system is locked.**

**3. Write what the name must NOT do.**

**4. Create the sound.**

**5. Rewrite it several times from scratch.**

**6. Experiment with spelling.**

**7. Compare it with neighboring names.**

**8. Look for accidental roots and relationships.**

**9. Ask whether those relationships reveal history.**

**10. Test multiple pronunciations.**

**11. Decide whether an English translation would be stronger.**

**12. Keep the old name unless the replacement genuinely improves the world around it.**

# 28. Core Philosophy

The names pass should make GameBibleV2 feel **less authored**, not more elaborate.

Names should appear to have survived:

- migration;
- conquest;
- bad maps;
- religious conversion;
- translation;
- administrative reform;
- prejudice;
- language drift;
- family habit;
- political propaganda;
- jokes;
- ordinary laziness.

The setting should not feel as though one person sat down and named everything using a single fantasy vocabulary.

Some names should be beautiful.

Some should be ugly.

Some should be boring.

Some should be translations.

Some should be ancient words nobody understands anymore.

Some should technically mean the wrong thing because history changed after the name became fixed.

Some places should have two names and an argument about which one is correct.

That mess is part of what makes names feel inherited rather than invented.

**Do not make every name impressive. Make every important name belong.**

## Existing source notices and deliberate limits

The same source notices found in Pass One remain:

- 893 ambiguous source/target pairs.
- 28 missing source/target pairs.
- 7 missing heading/block references.
- 48 malformed-metadata warnings in archived material.

No current Base produces an unsupported-expression warning. Future plugin functions, arithmetic, scripts, inline Base code blocks, custom summaries and unsupported view options are not silently emulated. They receive explicit compatibility notices.

The reader follows the files’ filters literally. Missing properties are null, not an empty string. Consequently, `map_id != ""` alone does not require a map ID to exist, and a Base testing `status != "canon"` can include attachments. This is not corrected by inventing extra filters. Missing sort values appear last. File membership is restricted to the six approved trees and allowed attachment types, not hidden settings or application files.

Browsing and filtering do not authenticate a source, settle its authority or rewrite metadata. The in-memory indexes remain rebuildable; there is no content database or publishing copy.
